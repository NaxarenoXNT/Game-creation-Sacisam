## Visión General

El sistema de IA usa **árboles de comportamiento (Behavior Trees)** para la lógica de decisión en combate, y una **FSM** para la deambulación en el mundo abierto. Las dos capas son independientes: el Behavior Tree solo corre durante el combate, la FSM solo corre fuera de él.

**Behavior Tree (combate)**:
- **Rol** (`IDecisionRol`): define la estrategia. Es independiente de la raza del enemigo.
- **Nodos** (`NodoIA`): átomos reutilizables (condiciones, acciones) que cada rol compone.
- **`ContextoIA`**: blackboard estático compartido entre nodos — el nodo de acción escribe en `UltimoResultado` y el rol lo retorna.

**FSM (roaming)**:
- Estados: `Idle` → `Patrol` → `Alerted` → `Chasing` → combate / vuelta a `Patrol`/`Idle`.
- `PlayerDetector` se actualiza cada 0.3 s y evalúa distancia + línea de visión.

```
EnemigoData.arquetipoIA (enum)
        │
        ▼
CerebroIA.CrearParaArquetipo()
        │  busca en el registry estático
        ▼
IDecisionRol (ej: RolSanador)
        │  compone un árbol de NodoIA y lo evalúa cada turno
        ▼
ContextoIA.UltimoResultado { Objetivo, Habilidad }
        │
        ▼
Enemigos.ObtenerAccionElegida() → CombateManager
```

## IDecisionRol

**Archivo**: `Assets/Scripts/IA/Roles/IDecisionRol.cs`

Contrato que debe implementar cada archivo de rol.

```csharp
public interface IDecisionRol
{
    ResultadoIA Decidir(
        Enemigos yo,
        List<IEntidadCombate> jugadores,
        List<IEntidadCombate> aliados
    );
}
```

El rol recibe al enemigo que actua, la lista de jugadores (objetivos hostiles) y los aliados (otros enemigos en combate). Retorna un `ResultadoIA` con el objetivo elegido y la habilidad a usar, o `null` si no hay accion valida.

## CerebroIA

**Archivo**: `Assets/Scripts/IA/Core/CerebroIA.cs`

Coordina la toma de decisiones. No contiene lógica de combate propia. Es `[Serializable]` para poder guardarse con el estado del enemigo.

### Registry estático

Mapea `ArquetipoIA` a `IDecisionRol`. Agregar una línea para registrar roles nuevos.

```csharp
private static readonly Dictionary<ArquetipoIA, Func<IDecisionRol>> _registry = new()
{
    { ArquetipoIA.Basico,      () => new RolBasico()      },
    { ArquetipoIA.Guerrero,    () => new RolGuerrero()    },
    { ArquetipoIA.Mago,        () => new RolMago()        },
    { ArquetipoIA.Sanador,     () => new RolSanador()     },
    { ArquetipoIA.Berserk,     () => new RolBerserk()     },
    { ArquetipoIA.Tanque,      () => new RolTanque()      },
    { ArquetipoIA.Controlador, () => new RolControlador() },
    { ArquetipoIA.Soporte,     () => new RolSoporte()     },
};
```

Si el arquetipo no está registrado, `CrearParaArquetipo()` usa `RolBasico` como fallback y emite un `Debug.LogWarning`.

### Uso

```csharp
// Al inicializar desde EnemigoData (Enemigos.InicializarDesdeEnemigoData)
CerebroIA = CerebroIA.CrearParaArquetipo(datos.arquetipoIA);
CerebroIA.Configurar(this);  // vincula el cerebro con su enemigo dueño

// Cada turno (Enemigos.ObtenerAccionElegida)
var resultado = CerebroIA.Decidir(jugadores, aliados);
if (resultado?.Habilidad != null)
    return (resultado.Habilidad, resultado.Objetivo);
```

### Helpers legacy (compatibilidad)

```csharp
CerebroIA.CrearBasico()    // → CrearParaArquetipo(Basico)
CerebroIA.CrearAgresivo()  // → CrearParaArquetipo(Guerrero)
CerebroIA.CrearDefensivo() // → CrearParaArquetipo(Tanque)
```

## NodoIA

**Archivo**: `Assets/Scripts/IA/Core/NodoIA.cs`

Clase base abstracta para todos los nodos del árbol. Expone helpers de selección de habilidades disponibles en todos los nodos.

```csharp
public abstract class NodoIA
{
    protected Enemigos enemigo;
    protected List<IEntidadCombate> jugadores;
    protected List<IEntidadCombate> aliados;

    public void Configurar(Enemigos enemigo, List<IEntidadCombate> jugadores, List<IEntidadCombate> aliados);
    public abstract EstadoNodo Evaluar();
    public virtual void Resetear() { }

    // Helpers disponibles en todos los nodos:
    protected HabilidadData SeleccionarHabilidadOfensiva(IEntidadCombate objetivo, params CategoriaHabilidad[] prioridades);
    protected HabilidadData SeleccionarHabilidadSoporte(IEntidadCombate objetivo, params CategoriaHabilidad[] prioridades);
    protected IEntidadCombate AliadoMasHerido();
    protected IEntidadCombate AliadoMasFuerte();
}
```

`SeleccionarHabilidadOfensiva` recorre el `GestorHabilidades` del enemigo, filtra por cooldown y `EsViable`, y retorna la primera habilidad que coincide con las categorías indicadas en orden de prioridad. Usa `HabilidadPorDefecto` como fallback.

`AliadoMasHerido()` incluye al propio enemigo en la comparación (se puede curar a sí mismo si es el más herido).

### ResultadoIA

```csharp
public class ResultadoIA
{
    public IEntidadCombate Objetivo   { get; set; }
    public HabilidadData   Habilidad  { get; set; }
    public TipoAccionIA    TipoAccion { get; set; }

    public enum TipoAccionIA { Atacar, Defender, Huir, Curar, Buff, Debuff, Control, Especial }
}
```

### ContextoIA (blackboard)

```csharp
public static class ContextoIA
{
    public static ResultadoIA UltimoResultado { get; set; }
}
```

Actúa como blackboard compartido. Los nodos de acción escriben en `UltimoResultado`; el rol lo lee al final de `Evaluar()`. Es estático, por lo que **solo puede haber un árbol evaluándose a la vez** (válido ya que el combate es por turnos).

## Nodos de Control (Compuestos)

**Archivo**: `Assets/Scripts/IA/Nodos/NodosCompuestos.cs`

### Selector
Prueba hijos en orden. Retorna `Exito` en cuanto uno tiene éxito. Si todos fallan, retorna `Fallo`.

### Secuencia
Ejecuta hijos en orden. Retorna `Fallo` en cuanto uno falla. Si todos tienen éxito, retorna `Exito`.

### SelectorAleatorio
Elige un hijo al azar y lo ejecuta. Retorna su resultado directamente.

## Nodos de Condición

**Archivo**: `Assets/Scripts/IA/Nodos/NodosCondicionales.cs`

| Clase | Descripción |
|-------|-------------|
| `CondicionVidaBaja(umbral)` | Verdadero si el enemigo tiene `<= umbral%` de HP |
| `CondicionJugadorDebil(umbral)` | Verdadero si algún jugador tiene `<= umbral%` de HP |
| `CondicionAliadoHerido(umbral)` | Verdadero si algún aliado (o el propio enemigo) tiene `<= umbral%` HP |
| `CondicionAliadosCaidos(n)` | Verdadero si al menos n aliados están muertos |
| `CondicionProbabilidad(p)` | Verdadero con probabilidad p (0 a 1) |

## Nodos de Acción

**Archivo**: `Assets/Scripts/IA/Nodos/NodosAccion.cs`

Todos los nodos de acción usan los helpers de `NodoIA` para seleccionar la habilidad real del `GestorHabilidades`. Nunca hardcodean una habilidad. Al tener éxito, escriben en `ContextoIA.UltimoResultado`.

| Clase | Objetivo elegido | Categorías priorizadas |
|-------|------------------|------------------------|
| `AccionAtacarDebil` | Jugador con menor % HP | Ataque, Debuff, Control |
| `AccionAtacarTank` | Jugador con mayor HP absoluto | Ataque, Debuff |
| `AccionAtacarAleatorio` | Jugador aleatorio vivo | Ataque, Debuff, Control |
| `AccionControlarObjetivo` | Jugador con menor % HP | Control, Debuff, Ataque |
| `AccionCurarAliado` | Aliado con menor % HP (incl. yo) | Curación |
| `AccionBuffearAliado` | Aliado con mayor HP (fallback: yo) | Buff, Curación |
| `AccionCurarse` | El propio enemigo | Curación, Buff |

Si el nodo no encuentra habilidad disponible (cooldown, sin recursos, no existe), retorna `Fallo` y el árbol prueba la siguiente rama.

## Roles de Combate

**Carpeta**: `Assets/Scripts/IA/Roles/`

Cada rol implementa `IDecisionRol`. Es **universal**: el mismo rol funciona para cualquier raza de enemigo. La raza afecta stats y habilidades; el rol afecta la estrategia. Son dimensiones ortogonales.

| Archivo | ArquetipoIA | Árbol de decisión |
|---------|-------------|-------------------|
| `RolBasico.cs` | `Basico` | VidaBaja(25%) + Prob(60%) → CurarsE; fallback AtacarAleatorio |
| `RolGuerrero.cs` | `Guerrero` | VidaBaja(20%) → Curarse; fallback AtacarDebil |
| `RolMago.cs` | `Mago` | VidaBaja(30%) → Curarse; Prob(45%) → Controlar; AtacarDebil |
| `RolSanador.cs` | `Sanador` | AliadoHerido(60%) → CurarAliado; VidaBaja(40%) → Curarse; Prob(50%) → Buffear; AtacarDebil |
| `RolBerserk.cs` | `Berserk` | AtacarTank; fallback AtacarAleatorio (sin autopreservación) |
| `RolTanque.cs` | `Tanque` | VidaBaja(50%) → Curarse; Prob(35%) → Buffear; AtacarTank |
| `RolControlador.cs` | `Controlador` | VidaBaja(25%) → Curarse; Prob(65%) → Controlar; AtacarDebil |
| `RolSoporte.cs` | `Soporte` | AliadoHerido(70%) → CurarAliado; VidaBaja(35%) → Curarse; Prob(50%) → Buffear; AtacarAleatorio |

`RolSanador` tiene `Decidir()` como `virtual` para permitir herencia sin reescribir todo.

## Agregar un Rol Nuevo

Ejemplo: rol `Invocador` que prioriza habilidades de Utilidad.

### Paso 1 - Agregar el valor al enum

```csharp
// Flags/TipoRecurso.cs
public enum ArquetipoIA
{
    // ... existentes ...
    Invocador,
}
```

### Paso 2 - Crear el archivo del rol

```csharp
// Assets/Scripts/IA/Roles/RolInvocador.cs
namespace IA.Roles
{
    public class RolInvocador : IDecisionRol
    {
        public ResultadoIA Decidir(Enemigos yo, List<IEntidadCombate> jugadores, List<IEntidadCombate> aliados)
        {
            var arbol = new Selector(
                new Secuencia(
                    new CondicionVidaBaja(0.30f),
                    new AccionCurarse()
                ),
                new Secuencia(
                    new CondicionProbabilidad(0.70f),
                    new AccionControlarObjetivo()
                ),
                new AccionAtacarAleatorio()
            );
            arbol.Configurar(yo, jugadores, aliados);
            arbol.Evaluar();
            return ContextoIA.UltimoResultado;
        }
    }
}
```

### Paso 3 - Registrar en CerebroIA

```csharp
// CerebroIA.cs - una sola linea en el registry
{ ArquetipoIA.Invocador, () => new RolInvocador() },
```

### Paso 4 - Asignar en Unity

En el `EnemigoData` del asset -> campo **Arquetipo IA** -> `Invocador`.

## Variante de Rol (herencia)

Si un tipo de enemigo necesita una variacion pequena sobre un rol existente:

```csharp
// RolSanadorAgresivo.cs - cura menos seguido, ataca mas
public class RolSanadorAgresivo : RolSanador
{
    public override ResultadoIA Decidir(Enemigos yo, List<IEntidadCombate> jugadores, List<IEntidadCombate> aliados)
    {
        var arbol = new Selector(
            new Secuencia(new CondicionAliadoHerido(0.35f), new AccionCurarAliado()),
            new Secuencia(new CondicionVidaBaja(0.25f), new AccionCurarse()),
            new AccionAtacarDebil(),
            new AccionAtacarAleatorio()
        );
        arbol.Configurar(yo, jugadores, aliados);
        arbol.Evaluar();
        return ContextoIA.UltimoResultado;
    }
}
```

Registrar como arquetipo nuevo:
```csharp
{ ArquetipoIA.SanadorAgresivo, () => new RolSanadorAgresivo() },
```

## Sistema de Deambulación (Roaming FSM)

**Carpeta**: `Assets/Scripts/IA/Roaming/`

Sistema de comportamiento fuera de combate. Controla el movimiento del enemigo en el mundo abierto. Es completamente independiente del Behavior Tree de combate.

### Estados y transiciones

```
       ┌─────────────────────────────────────────┐
       │                                         │
       ▼                                         │
   [Idle] ──── maxIdleTime(5s) / hay waypoints ──► [Patrol]
       │                                             │
       │ player detectado                            │ player detectado
       ▼                                             ▼
   [Alerted] ◄──────────────────────────────── [Alerted]
       │                                             │
       │ alertTime >= 2s + playerInChaseRange        │
       ▼                                             │
   [Chasing] ◄───────────────────────────────────────┘
       │
       ├── dentro de 3f → TryInitiateCombat() → COMBATE
       │
       ├── player fuera de rango → [Alerted]
       │
       └── timeout (15s) → [Patrol] / [Idle]

   [Resting] ──── restTime >= 10s → [Patrol] / [Idle]
              └── player detectado → [Alerted]
```

### EnemyRoamingFSM

**Archivo**: `Assets/Scripts/IA/Roaming/EnemyRoamingFSM.cs`

FSM principal. Contiene instancias de los 5 estados y gestiona las transiciones.

| Método | Descripción |
|--------|-------------|
| `Update()` | Actualiza `PlayerDetector`, llama `OnUpdate()` + `CheckTransitions()` del estado actual |
| `FixedUpdate()` | Llama `OnFixedUpdate()` del estado actual |
| `ChangeState(newState)` | `OnExit()` → cambia → `OnEnter()` |
| `ForceState(EnemyAIState)` | Fuerza un estado por enum |
| `Pause()` / `Resume()` | Pausa/reanuda la FSM |
| `Reset()` | Resetea el detector y vuelve al estado inicial |

### PlayerDetector

**Archivo**: `Assets/Scripts/IA/Roaming/PlayerDetector.cs`

- Cachea referencias al transform del jugador vía `PlayerPartyManager.Instance.MainCharacter` (fallback por tag).
- Radios obtenidos de `SpawnConfig > DatosEnemigo`, con default `15f` (detección) / `25f` (chase).
- Polling cada `0.3 s`, calcula distancia y actualiza `playerDetected`, `playerInChaseRange`, `lastKnownPlayerPosition`.
- `HasLineOfSight()` usa Raycast.
- `GetCurrentDetectionRadius(state)` aplica multiplicadores según el estado activo.

### RoamingState (base)

**Archivo**: `Assets/Scripts/IA/Roaming/RoamingState.cs`

Clase abstracta base. Todos los estados heredan de ella.

| Método | Descripción |
|--------|-------------|
| `Initialize(fsm, controller)` | Cachea referencias |
| `OnEnter()` / `OnExit()` | Ciclo de vida del estado |
| `OnUpdate()` / `OnFixedUpdate()` | Lógica por frame |
| `CheckTransitions()` | Retorna el próximo estado o `null` si sin cambio |

### Estados

| Estado | Comportamiento |
|--------|----------------|
| `IdleState` | Detiene velocidad; espera `maxIdleTime = 5s`; si hay waypoints → `Patrol` |
| `PatrolState` | Mueve entre waypoints; soporta `Loop`, `PingPong`, `Random`, `Once`; guarda `currentWaypointIndex` en `SpawnConfig` |
| `AlertedState` | Gira hacia el jugador (Slerp 3f); espera `alertDuration = 2s`; si player en rango chase → `Chasing`; si perdido y `alertTime >= 10s` → `Patrol`/`Idle` |
| `ChasingState` | Persigue al jugador a `patrolSpeed * 1.5f`; dentro de `3f` → `TryInitiateCombat()`; timeout `15s` → `Patrol`/`Idle` |
| `RestingState` | Espera `maxRestTime = 10s`; si player detectado → `Alerted` (radio reducido por `PlayerDetector`) |

`TryInitiateCombat()` en `ChasingState` llama a `encounterManager.RequestCombatFromEnemy(controller)`.
