# UI del proyecto Saclisam

## Visión general
La UI del proyecto se divide en dos bloques principales:

1. **UI Reactiva** (HUDs y paneles con bindings automáticos).
2. **UI de Combate** (panel de personaje y selección de objetivos).

El objetivo es evitar el polling en `Update()` y centralizar la actualización visual mediante **observables**, eventos y un **controlador de UI** por sistema.

## Arquitectura Simplificada

### Flujo de UI de Combate

```
EventoEncounterIniciado
        ↓
GameFlowController → Push(CombatFlowState)
        ↓
CombatFlowState.Enter() → SetContext(InputContext.Combat)
        ↓
EventoCombateIniciado
        ↓
CombatUIController (activa combatUIRoot, gestiona UI de combate)
        ↓
EventoEsperandoAccionJugador
        ↓
CombatCharacterPanel (muestra info + botones de acción)
        ↓
Click en "Habilidades" → Panel dinámico de AbilityButtonUI
        ↓
Selección de habilidad → EventoAccionSeleccionada
        ↓
CombatUIController escucha → Muestra TargetSelector
        ↓
Selección de objetivo → EventoObjetivoSeleccionado
        ↓
CombateManager ejecuta la acción
        ↓
EventoCombateFinalizado
        ↓
GameFlowController → Pop() → ExplorationFlowState.Enter()
```

> **Nota:** `CombatUIController` ya no cambia `InputContext` directamente.
> El cambio de contexto de input es responsabilidad del `GameFlowController`
> a través de los estados `CombatFlowState` / `ExplorationFlowState`.
> Ver [29_Stack_FlowController](29_Stack_FlowController.md).

## 1) UI Reactiva (Core)

### Observable<T>
**Archivo:** `Assets/Scripts/UI/Core/Observable.cs`

- Contenedor de valor con notificación de cambios.
- Cuando cambia `Valor`, dispara `OnCambiado`.

### IBindableUI
**Archivo:** `Assets/Scripts/UI/Core/IBindableUI.cs`

- Interfaz mínima: `Refrescar()`.

### EntidadUIModel
**Archivo:** `Assets/Scripts/UI/Core/EntidadUIModel.cs`

- Modelo observable para entidades.
- Propiedades: `Nombre`, `VidaActual`, `VidaMaxima`, `ManaActual`, `ManaMaximo`, `Nivel`, `EstaVivo`, `EsSuTurno`.

## 2) UI Reactiva (Componentes)

### BarraReactiva
- Barra animada con Lerp y Gradient.
- Se vincula a `Observable<int>`.

### PanelEntidad
- Panel completo: nombre, nivel, barras, indicador de turno.
- Se vincula a `EntidadUIModel`.

### TextoReactivo
- Texto con binding a función o observable.

### BotonHabilidad
- Botón con cooldown visual (para HUD fuera de combate).
- Usa `GestorCooldowns`.

## 3) UI de Combate

### CombatUIController
**Archivo:** `Assets/Scripts/UI/Combat/CombatUIController.cs`

**Responsabilidad:**
- Singleton coordinador de UI de combate.
- Escucha eventos del `EventBus`.
- Gestiona highlight del personaje activo.
- Controla el `TargetSelector`.
- Cambia contexto de input.

**Eventos escuchados:**
- `EventoCombateIniciado` → Activa UI, cambia a InputContext.Combat
- `EventoCombateFinalizado` → Oculta UI, restaura InputContext
- `EventoEsperandoAccionJugador` → Muestra highlight
- `EventoTurnoFinalizado` → Limpia estado
- `EventoAccionSeleccionada` → Muestra TargetSelector si necesita objetivo

**Estados (`CombatUIState`):**
- `Hidden` - UI oculta
- `ShowingCharacterPanel` - Panel de personaje visible
- `SelectingTarget` - Seleccionando objetivo

### CombatCharacterPanel
**Archivo:** `Assets/Scripts/UI/Combat/CombatCharacterPanel.cs`

**Función:**
- Panel ÚNICO de acciones de combate.
- Muestra info del personaje clickeado.
- Habilita botones solo si es el turno del personaje mostrado.

**Componentes visuales:**
- Imagen, nombre, nivel del personaje
- Barra de vida animada
- Barra de mana animada
- Botones: Habilidades, Usar Item, Defender
- Panel dinámico de habilidades (AbilityButtonUI)
- Contenedores de buffs/debuffs (placeholder)
- Botón de refuerzos (solo visible si `HayRefuerzosDisponibles()`)

**Flujo:**
1. Click en personaje → `MostrarPersonaje(entity)`
2. Si es su turno → Botones habilitados
3. Click "Habilidades" → Panel dinámico con AbilityButtonUI
4. Click en habilidad → `EventoAccionSeleccionada`
5. "Defender" → `EventoObjetivoSeleccionado` (self-target)

### AbilityButtonUI
**Archivo:** `Assets/Scripts/UI/Combat/AbilityButtonUI.cs`

**Función:**
- Botón de habilidad para el panel dinámico.
- Muestra: nombre, icono, daño estimado, tipo objetivo, costo, efecto.
- Colores por estado (disponible, cooldown, sin recurso).

### TargetSelector
**Archivo:** `Assets/Scripts/UI/Combat/TargetSelector.cs`

**Función:**
- Modo de selección de objetivos.
- Crea indicadores sobre aliados/enemigos válidos.
- Filtra según `TargetType` de la habilidad.

## 5) Cómo configurar en Unity

### Jerarquía recomendada:
```
Canvas (Combat)
├── CombatUIRoot (GameObject con CombatUIController)
│   ├── CombatCharacterPanel
│   │   ├── PanelInfo (nombre, nivel, imagen)
│   │   ├── Barras (vida, mana)
│   │   ├── BotonesAccion (Habilidades, Usar Item, Defender)
│   │   ├── PanelHabilidades (con ScrollRect + Contenedor)
│   │   ├── Buffs/Debuffs (contenedores)
│   │   └── BotonRefuerzos
│   └── TargetSelector
└── (Otros paneles no-combate)
```

### Inspector de CombatUIController:
- `combatUIRoot` → Root del canvas de combate
- `characterPanel` → Referencia a CombatCharacterPanel
- `targetSelector` → Referencia a TargetSelector
- `playerTurnHighlightPrefab` → Prefab de highlight

### Inspector de CombatCharacterPanel:
- Referencias a textos, imágenes, barras
- `prefabBotonHabilidad` → Prefab de AbilityButtonUI
- `contenedorHabilidades` → Transform padre para botones dinámicos

## 8) Notas de implementación

### Botón de Refuerzos
Solo aparece si `PlayerPartyManager.Instance.HayRefuerzosDisponibles()` retorna `true`.
Esto significa que hay personajes estacionados que pueden unirse al combate.

### Panel de Habilidades
Se genera dinámicamente según `personaje.HabilidadesDisponibles`.
Cada botón muestra:
- Nombre de la habilidad
- Daño calculado (ATK del personaje + escalado)
- Estado (disponible/cooldown/sin recursos)
- Icono de elemento

### Buffs/Debuffs
Los contenedores están preparados pero la lógica de mostrar iconos
está pendiente de integración con el sistema de estados.
